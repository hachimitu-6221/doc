- SIMT：single instruction multiple-threads
- 每个SM最多可以同时跟踪64个线程束（2,048个线程）。
- Blackwell GPU每个SM具有64K个32位寄存器（共256 KB）和每个SM共256 KB的L1缓存/共享内存。其中最多228 KB（227 KB可用）可以配置为每个SM的用户管理共享内存。
- 任何单个线程块最多可以请求227 KB的动态共享内存（CUDA保留了228 KB中的1 KB）。
- Blackwell 每个 SM 有 4 个 Warp Scheduler，每个 Scheduler 每周期最多发射一条指令，因此整个 SM 理论上每周期最多发射 4 条 Warp 指令。不同流水线中的指令仍然可以并行执行。
- SFU使用专用的SFU流水线，独立于主INT32/FP32和加载/存储（LD/ST）流水线运行。（可以做overlap）
- 每个周期最多四个线程束可以取得进展。例如，内存操作可以通过SM共16个加载/存储（LD/ST）流水线流动（每个调度器四个LD/ST流水线）。（1/4sm几个LD/ST?）
- CTA的语义和thread block相同；注意CTA和SM的区别，比如 `__syncthread()__` 是作用在CTA上而不是SM上
- 我们要尽可能保证高占用率，但高占用率必须与每线程资源限制（如寄存器和共享内存）相平衡。将寄存器溢出到较慢的内存可能会产生新的停顿。
- 线程块独立执行，且没有保证的顺序。这允许GPU调度器将它们分发到所有SM，并充分利用硬件并行性。
- 通常选择32的精确倍数的线程块大小。例如，一个256线程的块（8个线程束 = 256 / 32）完全占用每个线程束，而一个33线程的块将需要两个线程束槽位，并且只使用第二个线程束通道的1/32。
- B200

| 资源           | 硬件限制     | 说明                                           |
| ------------ | -------- | -------------------------------------------- |
| 线程束大小        | 32个线程    | 基本SIMT执行单元是32个线程（一个线程束）。始终使用32的倍数以避免浪费。      |
| 每个线程块的最大线程数  | 1,024个线程 | blockDim.x * blockDim.y * blockDim.z ≤ 1024。 |
| 每个线程块的最大线程束数 | 32个线程束   | (1,024个线程 / 32个线程每线程束) = 每个块最多32个线程束。        |
- 一个 SM 能同时容纳的 Warp 和 CTA（Thread Block）数量是有限的，因此你设置的 Block Size 会影响 SM 的 Occupancy（占用率）。

$$
 \text{Occupancy}=\frac{\text{SM 上实际驻留的 Warp 数}}{\text{SM 支持的最大驻留 Warp 数}} 
$$
- SM驻留资源限制（Blackwell B200）

|资源（每SM）|硬件限制|说明|
|---|---|---|
|每SM最大驻留线程束数|64个线程束|硬件可以保持最多64个线程束在运行（64 x 32个线程 = 2,048个线程）。注意：此限制已保持多代，对Blackwell仍然成立。|
|每SM最大驻留线程数|2,048个线程|等于64个线程束 x 32个线程/线程束。如果每个块使用1,024个线程，则最多2个这样的块（64个线程束）可以同时驻留在一个SM上。使用较小的块（例如256个线程）允许更多块驻留在SM上（最多8个块 x 256 = 2,048个线程），这可以增加占用率并帮助隐藏延迟--尽管太多的小块可能增加调度开销。|
|每SM最大活动块数|32个块|最多32个线程块可以同时驻留在一个SM上（如果块较小，更多块可以适应此限制）。|
