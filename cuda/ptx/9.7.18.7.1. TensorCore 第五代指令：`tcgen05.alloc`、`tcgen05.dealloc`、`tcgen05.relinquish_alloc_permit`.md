## `tcgen05.alloc`、`tcgen05.dealloc`、`tcgen05.relinquish_alloc_permit`

用于动态管理张量内存（Tensor Memory，TMEM）分配的指令。

## 语法

```ptx
tcgen05.alloc{.exclusive}.cta_group.sync.aligned{.shared::cta}.b32
    [dst], nCols;

tcgen05.dealloc{.exclusive}.cta_group.sync.aligned.b32
    taddr, nCols;

tcgen05.relinquish_alloc_permit.cta_group.sync.aligned;
```

```ptx
.cta_group = { .cta_group::1, .cta_group::2 }
```

## 描述

`tcgen05.alloc` 是一条阻塞指令，用于在张量内存中动态分配指定数量的列，并将已分配张量内存的地址写入地址操作数 `dst` 所指定的共享内存位置。

如果所请求数量的张量内存当前不可用，`tcgen05.alloc` 会阻塞；一旦有足够数量的张量内存可供分配，该指令就会解除阻塞。

`tcgen05.dealloc` 是一条可能阻塞的指令，用于释放张量内存地址 `taddr` 所指定的张量内存。操作数 `taddr` 必须指向此前通过分配操作获得的张量内存。

如果指定 `.cta_group::2`：

- 发起指令的 warp 与 peer CTA 中的 warp，在尝试共同释放张量内存之前，必须先同步双方的张量内存访问；
- `tcgen05.dealloc` 可能会阻塞，以便与 peer CTA 中的 warp 共同完成释放操作。

kernel 中通过 `tcgen05.alloc` 分配的所有张量内存，都必须在 kernel 退出前使用 `tcgen05.dealloc` 显式释放。

32 位无符号操作数 `nCols` 指定要分配或释放的列数。分配和释放以 **32 列以及每列的全部 lane** 为单位。

在 CTA 的执行顺序中，任意两次分配之间，分配的列数不得增加。

如果未指定 `.exclusive`：

- `nCols` 必须是 2 的幂；
- 取值范围为 `[32, 512]`。

如果指定 `.exclusive`：

- `nCols` 必须是 32 的倍数；
- 在 `sm_100f` 目标上，取值范围为 `[32, 512]`；
- 在 `sm_107f` 目标上，取值范围为 `[32, 576]`。

表 58 列出了 `nCols` 的有效值。

### 表 58：非独占分配与独占分配的 `nCols` 取值

| 分配类型 | 最小列数 | 最大列数 | 列数模数 | 列数的 Popcount |
|---|---:|---|---:|---|
| 非独占分配 | 32 | 512 | 32 | `= 1`，即必须是 2 的幂 |
| 独占分配 `.exclusive` | 32 | `sm_100`、`sm_103`、`sm_110`：512；`sm_107`：576 | 32 | 无限制 |

`tcgen05.relinquish_alloc_permit` 指令表示：执行线程所在的 CTA 放弃分配张量内存的权利。

因此，当 CTA 中的任何线程执行过 `tcgen05.relinquish_alloc_permit` 后，该 CTA 再执行 `tcgen05.alloc` 都是非法的。

如果未指定状态空间，则使用通用寻址（Generic Addressing）。如果 `dst` 指定的地址不在 `.shared::cta` 状态空间的地址窗口内，则行为未定义。

可选的 `.exclusive` 限定符描述了对分配许可（allocation permit）的影响：

- **未指定 `.exclusive`**：执行非独占分配。指令会使用分配许可，但不会取得其所有权。多个非独占分配可以同时存在。
- **指定 `.exclusive`**：执行独占分配。指令会取得分配许可的所有权。独占分配存在期间，不得同时存在任何其他分配。独占分配通常会占用全部张量内存容量，但也可以只占用其中一部分。
- 当且仅当内存通过 `.exclusive` 分配时，才必须通过 `.exclusive` 释放。也就是说，分配与释放必须使用匹配的独占属性。

### 独占分配

`tcgen05.alloc.exclusive` 操作会执行一次独占分配，取得张量内存及分配许可的控制权。在使用对应的 `tcgen05.dealloc.exclusive` 操作释放之前，它必须是唯一存活的分配。

独占分配操作会阻塞，直到不存在其他存活的分配。在唯一存活的分配被释放之前，其他 CTA 不得进行分配，无论是独占分配还是非独占分配。

该唯一分配必须通过与之匹配的 `tcgen05.dealloc.exclusive` 释放，并且释放时的列数必须相同。释放后，分配许可才可再次使用。

独占分配操作分配的列数可以不是 2 的幂。

如果指定 `.cta_group::1`，唯一分配的所有权由单个 CTA 持有；如果指定 `.cta_group::2`，所有权由两个 peer CTA 共同持有。

`.cta_group` 限定符指定参与分配和释放操作的 CTA 数量：

- 指定 `.cta_group::1` 时，必须由 CTA 中的一个 warp 执行分配和释放；
- 指定 `.cta_group::2` 时，必须由每个 peer CTA 中的一个 warp 共同执行分配和释放，具体见“发起粒度（Issue Granularity）”一节。

指定 `.cta_group::2` 时，发起指令的 warp 必须确保 peer CTA 已经启动，并且其中的 warp 最终会参与集合操作。

同一个 kernel 中的所有 `tcgen05` 指令，必须为 `.cta_group` 限定符指定相同的值。

必需的 `.sync` 限定符表示：执行线程必须等待 warp 中的所有线程都执行同一条指令，然后才能恢复执行。

必需的 `.aligned` 限定符表示：warp 中的所有线程必须执行同一条指令。

在条件执行代码中，只有确定 warp 中的所有线程都会对条件得出相同判断结果时，才能使用该指令，否则行为未定义。

如果出现以下任一情况，指令行为未定义：

- warp 中的线程未使用相同的 `nCols` 值；
- warp 中有任何线程已经退出。

`tcgen05.alloc` 中的存储操作，在内存一致性模型中被视为弱内存操作。

## PTX ISA 说明

- 在 PTX ISA 8.6 版本中引入。
- 在 PTX ISA 9.4 版本中，引入对 `.exclusive` 限定符的支持。

## 目标 ISA 说明

支持以下架构：

- `sm_100a`；
- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_110f` 或更高架构。

`.exclusive` 限定符支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_110f` 或更高架构。

## 示例

### 示例 1：单 CTA 的非独占分配与释放

```ptx
tcgen05.alloc.cta_group::1.sync.aligned.shared::cta.b32
    [sMemAddr1], 32;

ld.shared.b32 taddr, [sMemAddr1];

// 使用 taddr……
// 更多分配及其使用……

tcgen05.dealloc.cta_group::1.sync.aligned.b32
    taddr, 32;

// 更多释放操作……

tcgen05.relinquish_alloc_permit.cta_group::1.sync.aligned;
```

### 示例 2：双 CTA 的独占分配与释放

```ptx
// 以下指令由当前 warp 和 peer CTA 中的 warp 共同执行：

tcgen05.alloc.cta_group::2.sync.aligned.shared::cta.b32
    [sMemAddr2], 32;

ld.shared.b32 taddr, [sMemAddr2];

// 使用 taddr……
// 更多分配及其使用……

tcgen05.dealloc.cta_group::2.sync.aligned.b32
    taddr, 32;

// 更多释放操作……

tcgen05.relinquish_alloc_permit.cta_group::2.sync.aligned;
```

### 示例 3：双 CTA 的独占分配与释放

```ptx
.reg .b32 sMemAddr, taddr;
.reg .u32 nCols;

mov.u32 nCols, 576;

tcgen05.alloc.exclusive.cta_group::2.sync.aligned.shared::cta.b32
    [sMemAddr], nCols;

// ...

tcgen05.dealloc.exclusive.cta_group::2.sync.aligned.b32
    taddr, nCols;

// ...

tcgen05.relinquish_alloc_permit.cta_group::2.sync.aligned;
```
