## `mbarrier.arrive`

对 `mbarrier` 对象执行 arrive-on（到达）操作。
### 语法
```ptx
mbarrier.arrive{.sem.scope}{.shared{::cta}}.b64                         state, [addr]{, count};
mbarrier.arrive{.sem.scope}{.shared::cluster}{.multicast}.b64           _, [addr] {,count} {, ctaMask};
mbarrier.arrive.expect_tx{.sem.scope}{.shared{::cta}}.b64               state, [addr], txCount;
mbarrier.arrive.expect_tx{.sem.scope}{.shared::cluster}{.multicast}.b64 _, [addr], txCount {, ctaMask};
mbarrier.arrive.noComplete{.release.cta}{.shared{::cta}}.b64            state, [addr], count;
```

```ptx
.sem      = { .release, .relaxed }
.scope    = { .cta, .cluster }
.multicast = { .multicast::cluster::32b }
```

### 描述

执行 `mbarrier.arrive` 的线程，会对地址操作数 `addr` 所指定位置的 `mbarrier` 对象执行 arrive-on 操作。32 位无符号整数操作数 `count` 指定 arrive-on 操作的 `count` 参数。

如果未指定状态空间，则使用通用寻址（Generic Addressing）。如果 `addr` 指定的地址不在 `.shared::cta` 状态空间的地址窗口内，则行为未定义。

操作数 `addr` 支持的寻址模式，如“地址作为操作数（Addresses as Operands）”一节所述。操作数 `addr` 的对齐要求，如“`mbarrier` 对象的大小与对齐（Size and alignment of mbarrier object）”一节所述。

可选限定符 `.expect_tx` 表示：在执行 arrive-on 操作之前，先执行一次 expect-tx 操作。32 位无符号整数操作数 `txCount` 指定 expect-tx 操作的 `expectCount` 参数。当同时指定 `.arrive` 和 `.expect_tx` 限定符时，arrive-on 操作的 `count` 参数默认为 1。

带有 `.noComplete` 限定符的 `mbarrier.arrive` 操作不得导致 `mbarrier` 完成其当前阶段，否则行为未定义。

操作数 `count` 的值必须位于“`mbarrier` 对象的内容（Contents of the mbarrier object）”一节所规定的范围内。

注意：对于 `sm_8x`，当指定 `count` 参数时，必须使用 `.noComplete` 修饰符。

对位于 `.shared::cta` 中的 `mbarrier` 对象执行 `mbarrier.arrive` 操作时，会在目标操作数 `state` 中返回一个不透明的 64 位值，该值记录 arrive-on 操作之前 `mbarrier` 对象所处的阶段。`state` 操作数的具体内容由实现决定。也可以选择使用丢弃符号（sink symbol）`_` 作为 `state` 参数。

如果 `mbarrier` 对象位于 `.shared::cluster` 中、但不在 `.shared::cta` 中，则对其执行的 `mbarrier.arrive` 操作不能返回值。在这种情况下，目标操作数必须使用丢弃符号 `_`。

可选的 `.sem` 限定符指定内存同步效果，具体语义如“内存一致性模型（Memory Consistency Model）”一节所述。如果省略 `.sem` 限定符，则默认使用 `.release`。

`.relaxed` 限定符不提供任何内存排序语义和可见性保证。

可选的 `.scope` 限定符指定能够直接观察到该操作内存同步效果的线程集合，具体如“内存一致性模型”一节所述。如果未指定 `.scope` 限定符，则默认为 `.cta`。相比之下，`.shared::<scope>` 表示的是 `mbarrier` 所在的状态空间。

`.sem` 和 `.scope` 限定符必须同时指定。

可选限定符 `.multicast::cluster::32b` 允许对 cluster 中多个 CTA 的共享内存里的 `mbarrier` 对象执行 arrive-on 操作，并可选择同时执行 expect-tx 操作。操作数 `ctaMask` 指定 cluster 中的目标 CTA；32 位 `ctaMask` 操作数中的每一位，都对应目标 CTA 的 `%cluster_ctarank`。例如，`ctaMask` 的值为 `0x1` 时，表示对 rank 为 0 的 CTA 执行操作；值为 `0x3` 时，表示对 rank 为 0 和 1 的 CTA 执行操作。

arrive-on 操作以及可选的 expect-tx 操作，会被多播到每个目标 CTA 的共享内存中，其位置均为与 `addr` 相同的 CTA 相对偏移处。

### PTX ISA 说明

- 在 PTX ISA 7.0 版本中引入。
- 在 PTX ISA 7.1 版本中，引入使用丢弃符号 `_` 作为目标操作数的支持。
- 在 PTX ISA 7.8 版本中，引入对 `.shared` 的子限定符 `::cta` 的支持。
- 在 PTX ISA 7.8 版本中，引入不带 `.noComplete` 修饰符时使用 `count` 参数的支持。
- 在 PTX ISA 8.0 版本中，引入对子限定符 `::cluster` 的支持。
- 在 PTX ISA 8.0 版本中，引入对 `.expect_tx` 限定符的支持。
- 在 PTX ISA 8.0 版本中，引入对 `.scope` 和 `.sem` 限定符的支持。
- 在 PTX ISA 8.6 版本中，引入对 `.relaxed` 限定符的支持。
- 在 PTX ISA 9.4 版本中，引入对 `.multicast::cluster::32b` 的支持。

### 目标 ISA 说明

- 需要 `sm_80` 或更高架构。
- 不带 `.noComplete` 修饰符而使用 `count` 参数，需要 `sm_90` 或更高架构。
- `.expect_tx` 限定符需要 `sm_90` 或更高架构。
- 子限定符 `::cluster` 需要 `sm_90` 或更高架构。
- `.cluster` 作用域需要 `sm_90` 或更高架构。
- `.relaxed` 限定符需要 `sm_90` 或更高架构。
- `.multicast::cluster::32b` 限定符支持以下特定架构家族：
  - 同一家族中的 `sm_107f` 或更高架构。

### 示例

```ptx
.reg .b32 cnt, remoteAddr32, remoteCTAId, addr32;
.reg .b64 %r<5>, addr, remoteAddr64;
.shared .b64 shMem, shMem2;

cvta.shared.u64            addr, shMem2;
mov.b32                    addr32, shMem2;
mapa.shared::cluster.u32   remoteAddr32, addr32, remoteCTAId;
mapa.u64                   remoteAddr64, addr,   remoteCTAId;

cvta.shared.u64          addr, shMem2;

mbarrier.arrive.shared.b64                       %r0, [shMem];
mbarrier.arrive.shared::cta.b64                  %r0, [shMem2];
mbarrier.arrive.release.cta.shared::cluster.b64  _, [remoteAddr32];
mbarrier.arrive.release.cluster.b64              _, [remoteAddr64], cnt;
mbarrier.arrive.expect_tx.release.cluster.b64    _, [remoteAddr64], tx_count;
mbarrier.arrive.noComplete.b64                   %r1, [addr], 2;
mbarrier.arrive.relaxed.cta.b64                  %r2, [addr], 4;
mbarrier.arrive.b64                              %r2, [addr], cnt;
mbarrier.arrive.release.cta.shared::cluster.multicast::cluster::32b.b64  _, [remoteAddr32], 0xa;
```
