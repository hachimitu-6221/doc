## `cp.async.bulk.tensor`

启动一次异步拷贝操作，将张量数据从一个状态空间拷贝到另一个状态空间。
## 语法
```ptx
// global -> shared::cta
cp.async.bulk.tensor.dim.dst.src{.load_mode}.completion_mechanism{.cta_group}{.level::cache_hint}{.override::global_address}{.override_attribute}
                                   [dstMem], [tensorMap{, gAddrToOverride}{, attributeOverrideInfo}, tensorCoords], [mbar]{, im2colInfo} {, cache_policy}

.dst =                  { .shared::cta }
.src =                  { .global }
.dim =                  { .1d, .2d, .3d, .4d, .5d }
.completion_mechanism = { .mbarrier::complete_tx::bytes{.report_mechanism} }
.cta_group =            { .cta_group::1, .cta_group::2 }
.load_mode =            { .tile, .tile::gather4, .im2col, .im2col::w, .im2col::w::128 }
.level::cache_hint =    { .L2::cache_hint }
.override_attribute =   { .override::global_dim, .override::global_dim_stride }
.report_mechanism =     { .mbarrier::report::disabled,
                          .mbarrier::report::validity::per_16bytes::80000000,
                          .mbarrier::report::validity::per_16bytes::8000,
                          .mbarrier::report::validity::per_16bytes::80,
                          .mbarrier::report::validity::per_16bytes::8,
                          .mbarrier::report::validity::per_element::ff
                        }


// global -> shared::cluster
cp.async.bulk.tensor.dim.dst.src{.load_mode}.completion_mechanism{.multicast}{.cta_group}{.level::cache_hint}{.override::global_address}{.override_attribute}
                                   [dstMem], [tensorMap{, gAddrToOverride}{, attributeOverrideInfo}, tensorCoords], [mbar]{, im2colInfo}
                                   {, ctaMask} {, cache_policy}

.dst =                  { .shared::cluster }
.src =                  { .global }
.dim =                  { .1d, .2d, .3d, .4d, .5d }
.completion_mechanism = { .mbarrier::complete_tx::bytes{.report_mechanism} }
.cta_group =            { .cta_group::1, .cta_group::2 }
.load_mode =            { .tile, .tile::gather4, .im2col, .im2col::w, .im2col::w::128 }
.level::cache_hint =    { .L2::cache_hint }
.multicast =            { .multicast::cluster{::16b, ::32b} }
.override_attribute =   { .override::global_dim, .override::global_dim_stride }
.report_mechanism =     { .mbarrier::report::disabled,
                          .mbarrier::report::validity::per_16bytes::80000000,
                          .mbarrier::report::validity::per_16bytes::8000,
                          .mbarrier::report::validity::per_16bytes::80,
                          .mbarrier::report::validity::per_16bytes::8,
                          .mbarrier::report::validity::per_element::ff
                        }


// shared::cta -> global
cp.async.bulk.tensor.dim.dst.src{.load_mode}.completion_mechanism{.level::cache_hint}{.override::global_address}{.override_attribute}
                                   [tensorMap{, gAddrToOverride}{, attributeOverrideInfo}, tensorCoords], [srcMem] {, cache_policy}

.dst =                  { .global }
.src =                  { .shared::cta }
.dim =                  { .1d, .2d, .3d, .4d, .5d }
.completion_mechanism = { .bulk_group }
.load_mode =            { .tile, .tile::scatter4, .im2col_no_offs, .im2col_no_offs::w }
.level::cache_hint =    { .L2::cache_hint }
.override_attribute =   { .override::global_dim, .override::global_dim_stride }
```
## 描述
`cp.async.bulk.tensor` 是一条非阻塞指令，它启动一次异步拷贝操作，将张量数据从 `.src` 状态空间中的位置拷贝到 `.dst` 状态空间中的位置。

操作数 `dstMem` 指定 `.dst` 状态空间中接收张量数据的目标位置；`srcMem` 指定 `.src` 状态空间中待拷贝张量数据的源位置。

当 `.dst` 指定为 `.shared::cta` 时，地址 `dstMem` 必须位于当前 cluster 中执行该指令的 CTA 的共享内存内，否则行为未定义。当 `.dst` 为 `.shared::cta` 时，`mbarrier` 对象 `mbar` 也必须位于执行该指令的 CTA 的共享内存中，否则行为未定义。如果 `mbarrier` 对象 `mbar` 位于 cluster 中另一个 CTA 的共享内存中，即远端 barrier，则 `.dst` 必须指定为 `.shared::cluster`，否则行为未定义。

当 `.dst` 指定为 `.shared::cluster` 时，地址 `dstMem` 可以位于当前 cluster 中任意 CTA 的共享内存内。

操作数 `tensorMap` 是一个不透明 tensor-map 对象的通用地址，该对象位于 `.param`、`.const` 或 `.global` 状态空间中。操作数 `tensorMap` 指定张量拷贝操作的属性，具体见“Tensor-map”一节。系统通过 tensormap 代理访问 `tensorMap`。关于如何在主机端创建 tensor-map 对象，请参阅《CUDA 编程指南》。

张量数据的维度由 `.dim` 修饰符指定。

向量操作数 `tensorCoords` 指定全局内存中张量数据的起始坐标，拷贝操作将从该位置读取数据，或将数据写入该位置。`tensorCoords` 中各个张量坐标的类型均为 `.s32`。向量参数 `tensorCoords` 的格式取决于所指定的 `.load_mode`，具体如下：

| `.load_mode` | `tensorCoords` | 语义 |
|---|---|---|
| `.tile::scatter4`、`.tile::gather4` | `{col_idx, row_idx0, row_idx1, row_idx2, row_idx3}` | 长度为 5 的固定长度向量。这五个元素共同指定四行的起始坐标。 |
| 其他所有模式 | `{d0, .., dn}`，其中 `n = .dim` | 包含 `n` 个元素的向量，其中 `n = .dim`。各元素表示对应维度上的偏移量。 |

修饰符 `.completion_mechanism` 指定该指令变体支持的完成机制。不同变体支持的完成机制如下：

| `.completion-mechanism` | `.dst` | `.src` | 完成整个异步操作所需的机制 | 可选用于完成 tensor-map 对象读取的机制 |
|---|---|---|---|---|
| `.mbarrier::...` | `.shared::cta` | `.global` | 基于 `mbarrier` | 基于 bulk async-group |
| `.mbarrier::...` | `.shared::cluster` | `.global` | 基于 `mbarrier` | 基于 bulk async-group |
| `.bulk_group` | `.global` | `.shared::cta` | 基于 bulk async-group | — |

修饰符 `.mbarrier::complete_tx::bytes` 表示该 `cp.async.bulk.tensor` 变体使用基于 `mbarrier` 的完成机制。异步拷贝操作完成后，会对操作数 `mbar` 指定的 `mbarrier` 对象执行 complete-tx 操作，其中 `completeCount` 参数等于实际拷贝的数据字节数。该指令通过 generic 代理访问其 `mbarrier` 操作数。

当 `mbarrier` 对象 `mbar` 位于 cluster 中另一个 CTA 的共享内存中，即远端 barrier 时，`.dst` 必须指定为 `.shared::cluster`。在这种情况下使用 `.shared::cta` 作为 `.dst`，不会向远端 barrier 发送信号，并会导致未定义行为。

修饰符 `.cta_group` 只能与基于 `mbarrier` 的完成机制一起使用。它用于向 CTA-Pair 中的奇数编号 CTA 或偶数编号 CTA 发送信号。

- 指定 `.cta_group::1` 时，所指定的 `mbarrier` 对象 `mbar` 必须与共享内存目标 `dstMem` 位于同一个 CTA 中。
- 指定 `.cta_group::2` 时，`mbarrier` 对象 `mbar` 可以位于与共享内存目标 `dstMem` 相同的 CTA 中，也可以位于其 peer-CTA 中。
- 如果未指定 `.cta_group`，则默认为 `.cta_group::1`。

修饰符 `.bulk_group` 表示该 `cp.async.bulk.tensor` 变体使用基于 bulk async-group 的完成机制。

限定符 `.load_mode` 指定如何将源位置的数据拷贝到目标位置。如果未指定 `.load_mode`，则默认为 `.tile`。

- 在 `.tile` 模式下，源张量的多维布局会在目标位置保留。
- 在 `.tile::gather4` 模式下，二维源张量中的四行会组合成一个二维目标张量。
- 在 `.tile::scatter4` 模式下，一个二维源张量会被拆分到二维目标张量的四行中。

`.tile::scatter4` 和 `.tile::gather4` 模式的详细信息，见“.tile::scatter4 和 .tile::gather4 模式”一节。

在 `.im2col`、`.im2col::*`、`.im2col_no_offs` 和 `.im2col_no_offs::w` 模式下，源张量的某些维度会在目标位置展开为一个单列。各种 im2col 模式的详细信息见“im2col 模式”一节。在这些模式下，张量至少必须是三维的。

只有当 `.load_mode` 为 `.im2col`、`.im2col::w` 或 `.im2col::w::128` 时，才能指定向量操作数 `im2colInfo`。向量参数 `im2colInfo` 的格式取决于具体的 im2col 模式：

| 具体 im2col 模式 | `im2colInfo` 参数 | 语义 |
|---|---|---|
| `.im2col` | `.dim = .5d` 时为 `{i2cOffW, i2cOffH, i2cOffD}` | im2col 偏移向量，其长度比 `.dim` 指定的维度数少 2。 |
| `.im2col::w`、`.im2col::w::128` | `{wHalo, wOffset}` | 包含 `wHalo` 和 `wOffset` 两个参数的向量。 |
| `.im2col_no_offs` | 不适用 `im2colInfo` | 不适用 `im2colInfo`。 |
| `.im2col_no_offs::w` | 不适用 `im2colInfo` | 不适用 `im2colInfo`；`wHalo` 和 `wOffset` 默认为 0。 |

参数 `wHalo` 是一个 16 位无符号整数，其有效值集合因加载模式而异：

- `im2col::w` 模式：有效范围为 `[0, 512)`；
- `im2col::w::128` 模式：有效范围为 `[0, 32)`。

参数 `wOffset` 是一个 16 位无符号整数，其有效值范围为 `[0, 32)`。

可选限定符 `.multicast::cluster` 允许将数据从全局内存拷贝到 cluster 中多个 CTA 的共享内存。操作数 `ctaMask` 指定 cluster 中的目标 CTA：16 位或 32 位 `ctaMask` 操作数中的每一位，分别对应目标 CTA 的 `%cluster_ctarank`。

附加子限定符 `::16b` 或 `::32b` 可用于指定 `ctaMask` 参数的宽度。默认情况下，`ctaMask` 被视为 16 位宽。

源数据会被多播到每个目标 CTA 的共享内存中，其偏移量与 `dstMem` 相同。

指定 `.cta_group` 时：

- `.cta_group::1`：`mbarrier` 信号被多播到目标 CTA 中与 `mbar` 相同的共享内存偏移处。
- `.cta_group::2`：对于 cluster 中每个可能的 CTA-Pair，`mbarrier` 信号会被多播到所有奇数编号 CTA，或所有偶数编号 CTA。具体而言，对于 `ctaMask` 指定的每个目标 CTA，系统会根据 `mbarrier` 对象 `mbar` 所在共享内存的 `%cluster_ctarank` 奇偶性，将信号发送到目标 CTA 或其 peer-CTA。

可选修饰符 `.override::global_address` 和 `.override_attribute` 支持覆盖 `tensorMap` 对象中各种张量属性的值。更多详细信息请参阅“覆盖张量属性值”一节。

指定可选参数 `cache_policy` 时，必须同时使用限定符 `.level::cache_hint`。64 位操作数 `cache_policy` 指定内存访问期间可使用的缓存逐出策略。

`cache_policy` 只是提供给缓存子系统的提示，缓存子系统不一定始终遵循。它仅被视为性能提示，不会改变程序的内存一致性行为。

可选限定符 `.report_mechanism` 指定 `mbarrier` 报告机制，具体见“异步拷贝操作的报告机制”一节。

`cp.async.bulk.tensor` 的拷贝操作被视为弱内存操作；对 `mbarrier` 执行的 complete-tx 操作具有 `.cluster` 作用域下的 `.release` 语义，具体见“内存一致性模型”一节。

## 注意事项

使用 `shared::cluster.global` 的拷贝操作针对以下目标架构进行了优化：

```text
sm_90a
sm_100f / sm_100a
sm_103f / sm_103a
sm_107a / sm_107f
sm_110f / sm_110a
```

在其他目标架构上，其性能可能会显著降低。因此，建议仅在上述 `.target` 下使用此类操作。

## PTX ISA 说明

- 在 PTX ISA 8.0 版本中引入。
- 在 PTX ISA 8.6 版本中，引入对 `.shared::cta` 作为目标状态空间的支持。
- 在 PTX ISA 8.6 版本中，引入对 `.tile::gather4` 和 `.tile::scatter4` 限定符的支持。
- 在 PTX ISA 8.6 版本中，引入对 `.im2col::w` 和 `.im2col::w::128` 限定符的支持。
- 在 PTX ISA 8.6 版本中，引入对 `.cta_group` 限定符的支持。
- 在 PTX ISA 9.4 版本中，引入对 `.multicast::cluster::16b` 和 `.multicast::cluster::32b` 限定符的支持。
- 在 PTX ISA 9.4 版本中，引入对 `.override::global_address` 和 `.override_attribute` 限定符的支持。
- 在 PTX ISA 9.4 版本中，引入对 `.im2col_no_offs::w` 限定符的支持。
- 在 PTX ISA 9.4 版本中，引入对 `.report_mechanism` 限定符的支持。

## 目标 ISA 说明

需要 `sm_90` 或更高架构。

`.multicast::cluster` 限定符建议与以下 `.target` 一起使用：

```text
sm_90a
sm_100f / sm_100a
sm_103f / sm_103a
sm_110f / sm_110a
```

`.tile::gather4` 和 `.im2col::w` 限定符要求：

- 当目标状态空间为 `.shared::cluster` 时，需要 `sm_100a`；从 PTX ISA 8.8 版本开始，也支持 `sm_100f`。
- 当目标状态空间为 `.shared::cta` 时，需要 `sm_100` 或更高架构。

`.tile::scatter4` 限定符支持以下架构：

- `sm_100a`；
- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_110f` 或更高架构。

`.im2col::w::128` 限定符支持以下架构：

- `sm_100a`；
- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_110f` 或更高架构。

`.cta_group` 限定符支持以下架构：

- `sm_100a`；
- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_110f` 或更高架构。

`.multicast::cluster::32b` 限定符支持以下特定架构家族：

- 同一家族中的 `sm_107f` 或更高架构。

.reg .u16 i2cOffW, i2cOffH, i2cOffD;

    [sMem0], [tensorMap0, {tc0}], [mbar0];

    [sMem2], [tensorMap2, {tc0, tc1, tc2, tc3, tc4}], [mbar2],
    {i2cOffW, i2cOffH, i2cOffD};

cp.async.bulk.tensor.1d.shared::cluster.global.mbarrier::complete_tx::bytes.tile
    [sMem0], [tensorMap0, {tc0}], [mbar0];

@p cp.async.bulk.tensor.2d.shared::cluster.global.mbarrier::complete_tx::bytes.multicast::cluster
    [sMem1], [tensorMap1, {tc0, tc1}], [mbar2], ctaMask;

@p cp.async.bulk.tensor.5d.shared::cluster.global.im2col.mbarrier::complete_tx::bytes
    [sMem2], [tensorMap2, {tc0, tc1, tc2, tc3, tc4}], [mbar2],
    {i2cOffW, i2cOffH, i2cOffD};

@p cp.async.bulk.tensor.3d.im2col.shared::cluster.global.mbarrier::complete_tx::bytes.L2::cache_hint
    [sMem3], [tensorMap3, {tc0, tc1, tc2}], [mbar3], {i2cOffW}, policy;

@p cp.async.bulk.tensor.1d.global.shared::cta.bulk_group
    [tensorMap3, {tc0}], [sMem3];

cp.async.bulk.tensor.2d.tile::gather4.shared::cluster.global.mbarrier::complete_tx::bytes
    [sMem5], [tensorMap6, {x0, y0, y1, y2, y3}], [mbar5];

cp.async.bulk.tensor.3d.im2col::w.shared::cluster.global.mbarrier::complete_tx::bytes
    [sMem4], [tensorMap5, {t0, t1, t2}], [mbar4], {im2colwHalo, im2colOff};

    [sMem6], [tensorMap7, {tc0}], [peerMbar];

cp.async.bulk.tensor.global.shared::cta.1d.bulk_group.tile.override::global_address.override::global_dim

cp.async.bulk.tensor.mbarrier::complete_tx::bytes.shared::cluster.global.4d.im2col::w::128.override::global_address.cta_group::1

cp.async.bulk.tensor.2d.shared::cluster.global.tile::gather4.mbarrier::complete_tx::bytes.mbarrier::report::validity::per_element::ff
