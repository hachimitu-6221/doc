membar, fence
强制内存操作之间的顺序。
**语法**
```ptx
// 线程 fence：
fence{.sem}.scope;

// 线程 fence：
fence.acquire.sync_restrict::shared::cluster.cluster;
fence.release.sync_restrict::shared::cta.cluster;

// 操作 fence：
fence.op_restrict.release.cluster;

// 代理 fence（双向）：
fence.proxy.proxykind;
fence.proxy.proxykind{.sem}.scope;

// 代理 fence（单向）：
fence.proxy.to_proxykind::from_proxykind.release.scope;
fence.proxy.to_proxykind::from_proxykind.acquire.scope  [addr], size;
fence.proxy.async::generic.acquire.sync_restrict::shared::cluster.cluster;
fence.proxy.async::generic.release.sync_restrict::shared::cta.cluster;
fence.proxy.async::generic.release.sync_restrict::shared::cluster::read.cluster;
fence.proxy.to_proxykind::from_proxykind_fabric.alias.sem_fabric.sys;

// 旧式 membar：
membar.level;
membar.proxy.proxykind;

.sem       = { .sc, .acq_rel, .acquire, .release };
.scope     = { .cta, .cluster, .gpu, .sys };
.level     = { .cta, .gl, .sys };
.proxykind = { .alias, .async, .async.global, .async.shared::{cta, cluster} };
.sem_alias  = { .acquire, .release };
.scope_alias = { .sys };
.op_restrict = { .mbarrier_init };
.to_proxykind::from_proxykind = {.tensormap::generic};
.to_proxykind::from_proxykind_fabric = {.generic::fabric, .fabric::generic, .fabric::fabric };
.sem_fabric = { .acquire, .release };
```

**描述**

`membar` 指令保证：本线程此前请求的内存访问（`ld`、`st`、`atom` 和 `red` 指令）在指定层级上被执行，先于本线程在 `membar` 指令之后请求的后续内存操作。level 限定符指定可能观察到该操作顺序效果的线程集合。

当读取的值已从内存传输出来，且在该指定层级上不能被其他线程修改时，一次内存读（例如由 `ld` 或 `atom` 执行）即被视为已执行。当写入的值已对指定层级上的其他线程可见，即之前的值不能再被读取时，一次内存写（例如由 `st`、`red` 或 `atom` 执行）即被视为已执行。

`fence` 指令按照内存一致性模型所述，在本线程请求的内存访问（`ld`、`st`、`atom` 和 `red` 指令）之间建立顺序。scope 限定符指定可能观察到该操作顺序效果的线程集合。

`fence.acq_rel` 是一种轻量级 fence，对大多数程序中的内存同步已经足够。`fence.acq_rel` 的实例在与额外的内存操作组合时产生同步，如内存一致性模型中 acquire 和 release 模式所述。如果缺少可选的 `.sem` 限定符，则默认假定为 `.acq_rel`。

`fence.sc` 是一种较慢的 fence，在足够多的地方使用时可以恢复顺序一致性，代价是性能。具有足够 scope 的 `fence.sc` 实例总是通过在运行时确定的每个 scope 的总顺序来同步。该总顺序可以进一步受到程序中其他同步的约束。

限定符 `.op_restrict` 和 `.sync_restrict` 限制 `fence` 指令为其提供内存顺序保证的内存操作类别。当 `.op_restrict` 为 `.mbarrier_init` 时，该 fence 的同步效果仅适用于同一线程此前对 `.shared::cta` 状态空间中的 `mbarrier` 对象执行的 `mbarrier.init` 操作。当 `.sync_restrict` 为 `.sync_restrict::shared::cta` 时，`.sem` 必须是 `.release`，且该 fence 的效果仅适用于对 `.shared::cta` 状态空间中对象执行的操作。同样，当 `.sync_restrict` 为 `.sync_restrict::shared::cluster` 时，`.sem` 必须是 `.acquire`，且该 fence 的效果仅适用于对 `.shared::cluster` 状态空间中对象执行的操作。当出现 `.sync_restrict::shared::cta` 或 `.sync_restrict::shared::cluster` 时，`.scope` 必须指定为 `.cluster`。

当 `.sync_restrict` 为 `.sync_restrict::shared::cluster::read` 时，`.sem` 必须是 `.release`，且该 fence 的效果仅适用于对 `.shared::cluster` 状态空间中对象执行的读操作。当存在该同步限制时，`.scope` 必须指定为 `.cluster`。

**注意**

`fence.proxy.async::generic.release.sync_restrict::shared::cluster::read.cluster` 是一种非累积的 fence 操作：它不会就因果序（Causality Order）传递地建立顺序。

地址操作数 `addr` 和操作数 `size` 一起指定内存范围 `[addr, addr+size-1]`，跨代理的内存访问顺序保证将在该范围上提供。`size` 操作数唯一支持的值是 `128`，且必须是常量整数字面量。无条件使用 Generic Addressing，且操作数 `addr` 指定的地址必须落在 `.global` 状态空间内。否则，行为未定义。

在 sm_70 及更高版本上，`membar` 是 `fence.sc` 的同义词，且 `membar` 的层级 `cta`、`gl` 和 `sys` 分别与 `fence` 的 scope `cta`、`gpu` 和 `sys` 同义。

`membar.proxy` 和 `fence.proxy` 指令在可能通过不同代理发生的内存访问之间建立顺序。

从 from-proxykind 到 to-proxykind 的单向代理顺序，在先前通过 from-proxykind 执行的内存访问与随后通过 to-proxykind 执行的内存访问之间建立顺序。

两个 proxykind 之间的双向代理顺序建立两个单向代理顺序：一个从第一个 proxykind 到第二个 proxykind，另一个从第二个 proxykind 到第一个 proxykind。

`.proxykind` 限定符指示在 generic 代理与 `.proxykind` 指定的代理之间进行的内存访问所建立的双向代理顺序。

双向代理 fence 不会像具有 `.release` 或 `.acquire` 语义的 fence 那样直接与其他 fence 同步。相反，双向代理 fence 在单个线程内生效，因此没有 `.scope` 限定符。它们的跨代理同步效果按照内存一致性模型的规则与其他形式的同步组合。

`.proxykind` 限定符的值 `.alias` 指使用虚拟别名地址对同一内存位置执行的内存访问。`.proxykind` 限定符的值 `.async` 指定在 async 代理与 generic 代理之间建立内存顺序。该内存顺序仅限于在指定状态空间中对象上执行的操作。如果未指定状态空间，则该内存顺序适用于所有状态空间。

一个 `.release` 代理 fence 可以形成一个 release 序列，与包含 `.acquire` 代理 fence 的 acquire 序列同步。`.to_proxykind` 和 `.from_proxykind` 限定符指示所建立的单向代理顺序。

在 sm_70 及更高版本上，`membar.proxy` 是 `fence.proxy` 的同义词。

¹ 随 sm_70 引入的 `fence.sc` 的语义是 `membar` 语义的超集，二者兼容；当在 sm_70 或更高架构上执行时，`membar` 获得 `fence.sc` 的完整语义。

**PTX ISA 说明**

`membar.{cta,gl}` 在 PTX ISA 版本 1.4 中引入。

`membar.sys` 在 PTX ISA 版本 2.0 中引入。

`fence` 在 PTX ISA 版本 6.0 中引入。

`membar.proxy` 和 `fence.proxy` 在 PTX ISA 版本 7.5 中引入。

`.cluster` scope 限定符在 PTX ISA 版本 7.8 中引入。

`.op_restrict` 限定符在 PTX ISA 版本 8.0 中引入。

`fence.proxy.async` 在 PTX ISA 版本 8.0 中引入。

`.to_proxykind::from_proxykind` 限定符在 PTX ISA 版本 8.3 中引入。

`fence` 指令的 `.acquire` 和 `.release` 限定符在 PTX ISA 版本 8.6 中引入。

`.sync_restrict` 限定符在 PTX ISA 版本 8.6 中引入。

`.to_proxykind::from_proxykind_fabric` 限定符在 PTX ISA 版本 9.3 中引入。

`.sync_restrict::shared::cluster::read` 限定符在 PTX ISA 版本 9.4 中引入。

带 `.alias` 限定符的 `.acquire` 和 `.release` 限定符在 PTX ISA 版本 9.4 中引入。

**目标 ISA 说明**

`membar.{cta,gl}` 在所有目标架构上支持。

`membar.sys` 需要 sm_20 或更高版本。

`fence` 需要 sm_70 或更高版本。

`membar.proxy` 需要 sm_60 或更高版本。

`fence.proxy` 需要 sm_70 或更高版本。

`.cluster` scope 限定符需要 sm_90 或更高版本。

`.op_restrict` 限定符需要 sm_90 或更高版本。

`fence.proxy.async` 需要 sm_90 或更高版本。

`.to_proxykind::from_proxykind` 限定符需要 sm_90 或更高版本。

`fence` 指令的 `.acquire` 和 `.release` 限定符需要 sm_90 或更高版本。

`.sync_restrict` 限定符需要 sm_90 或更高版本。

`.to_proxykind::from_proxykind_fabric` 限定符需要 sm_100 或更高版本。

`.sync_restrict::shared::cluster::read` 限定符需要 sm_90 或更高版本。

带 `.alias` 限定符的 `.acquire` 和 `.release` 限定符需要 sm_90 或更高版本。

**示例**

```ptx
membar.gl;
membar.cta;
membar.sys;
fence.sc.cta;
fence.sc.cluster;
fence.proxy.alias;
membar.proxy.alias;
fence.mbarrier_init.release.cluster;
fence.proxy.async;
fence.proxy.async.shared::cta;
fence.proxy.async.shared::cluster;
fence.proxy.async.global;

tensormap.replace.tile.global_address.global.b1024.b64   [gbl], new_addr;
fence.proxy.tensormap::generic.release.gpu;
cvta.global.u64  tmap, gbl;
fence.proxy.tensormap::generic.acquire.gpu [tmap], 128;
cp.async.bulk.tensor.1d.shared::cluster.global.tile  [addr0], [tmap, {tc0}], [mbar0];

// 通过 async 代理获取远端屏障状态。
barrier.cluster.wait.acquire;
fence.proxy.async::generic.acquire.sync_restrict::shared::cluster.cluster;

// 通过 generic 代理发布本地屏障状态。
mbarrier.init [bar];
fence.mbarrier_init.release.cluster;
barrier.cluster.arrive.relaxed;

// 通过 generic 代理获取本地共享内存。
mbarrier.try_wait.relaxed.cluster.shared::cta.b64 complete, [addr], parity;
fence.acquire.sync_restrict::shared::cluster.cluster;

// 通过 generic 代理发布本地共享内存。
fence.release.sync_restrict::shared::cta.cluster;
mbarrier.arrive.relaxed.cluster.shared::cluster.b64 state, [bar];

fence.proxy.generic::fabric.alias.release.sys;
fence.proxy.fabric::generic.alias.acquire.sys;

// 在生产者中通过 alias 代理发布。
st.weak.u32 [addr], value;
fence.proxy.alias.release.sys;
st.relaxed.sys [bar], 1;

// 在消费者中通过 alias 代理获取。
// when (ld.relaxed.sys [bar] == count):
fence.proxy.alias.acquire.sys;

// 通过 generic 代理发布本地共享内存（仅读操作）。
fence.proxy.async::generic.release.sync_restrict::shared::cluster::read.cluster;
```
