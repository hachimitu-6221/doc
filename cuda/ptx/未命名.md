# 9.7.18.8.3. TensorCore 第五代指令：`tcgen05.ld`

## `tcgen05.ld`

以异步、集合操作的方式，将数据从张量内存（Tensor Memory，TMEM）加载到寄存器中。

## 语法

### 基本加载指令

```ptx
tcgen05.ld.sync.aligned.shape1.num{.pack}.b32
    r, [taddr];

tcgen05.ld.sync.aligned.shape2.num{.pack}.b32
    r, [taddr], immHalfSplitoff;
```

```ptx
.shape1 = { .16x64b, .16x128b, .16x256b, .32x32b }
.shape2 = { .16x32bx2 }
.num    = { .x1, .x2, .x4, .x8, .x16, .x32, .x64, .x128 }
.pack   = { .pack::16b }
```

### 浮点类型加载并执行归约

```ptx
tcgen05.ld.red.sync.aligned.shape3.num.redOp{.abs}{.NaN}.f32
    r, redval, [taddr];

tcgen05.ld.red.sync.aligned.shape4.num.redOp{.abs}{.NaN}.f32
    r, redval, [taddr], immHalfSplitoff;
```

### 整数类型加载并执行归约

```ptx
tcgen05.ld.red.sync.aligned.shape3.num.redOp.type
    r, redval, [taddr];

tcgen05.ld.red.sync.aligned.shape4.num.redOp.type
    r, redval, [taddr], immHalfSplitoff;
```

```ptx
.shape3 = { .32x32b }
.shape4 = { .16x32bx2 }
.redOp  = { .min, .max }
.type   = { .u32, .s32 }
```

### 加载时执行稀疏压缩

```ptx
tcgen05.ld.spcompress.sync.aligned.shape.num.rowop.spfactor{.abs}.type.idxsize
    mdata, cdata, [taddr];

tcgen05.ld.red.spcompress.sync.aligned.shape.num.rowop.spfactor{.abs}{.NaN}.type.idxsize
    mdata, cdata, redval, [taddr];
```

```ptx
.shape    = { .32x32b }
.rowop    = { .min, .max }
.type     = { .f32 }
.idxsize  = { .b2 }
.spfactor = { .sp::2:4 }
.num      = { .x4, .x8, .x16, .x32, .x64, .x128 }
```

## 描述

`tcgen05.ld` 指令由 warp 中的所有线程集合执行，以异步方式将数据从 32 位地址操作数 `taddr` 指定的张量内存位置，加载到目标寄存器 `r` 中。

warp 中的所有线程必须为 `taddr` 指定相同的值，并且该值必须是集合加载操作的基地址，否则行为未定义。

`.shape` 限定符和 `.num` 限定符共同决定从张量内存加载的数据总维度：

- `.shape` 指定被访问数据的基本维度，具体见“数据移动形状（Data Movement Shape）”一节；
- `.num` 指定基本维度上的重复次数，由此得到实际访问的数据总维度。

`.16x32bx2` 形状会执行两次 `.16x32b` 形状的张量内存访问：

- 第一次访问的基地址由 `taddr` 指定；
- 第二次访问的基地址由 `taddr + immHalfSplitoff` 指定；
- `immHalfSplitoff` 是一个立即数参数。

目标操作数 `r` 是用花括号包围的向量表达式，根据 `.shape` 和 `.num` 的值，由一个或多个 32 位寄存器组成。不同 `.num` 和 `.shape` 组合对应的向量长度见表 59。

### 表 59：`.num` 与 `.shape` 的各种组合

| `.num` | `.16x32bx2`／`.16x64b`／`.32x32b` | `.16x128b` | `.16x256b` |
|---|---:|---:|---:|
| `.x1` | 1 | 2 | 4 |
| `.x2` | 2 | 4 | 8 |
| `.x4` | 4 | 8 | 16 |
| `.x8` | 8 | 16 | 32 |
| `.x16` | 16 | 32 | 64 |
| `.x32` | 32 | 64 | 128 |
| `.x64` | 64 | 128 | 不适用 |
| `.x128` | 128 | 不适用 | 不适用 |

限定符 `.red` 表示：对每个 lane 中跨列加载的数据，执行 `.redOp` 指定的归约操作。归约结果写入对应线程的 32 位目标寄存器操作数 `redVal` 中。

指定 `.red` 限定符时，`.num` 修饰符至少必须为 `.x2`。

如果指定 `.abs` 限定符，归约操作将使用所加载数据的绝对值。

如果指定 `.NaN` 限定符，当归约操作的任一输入为 NaN 时，归约结果为规范 NaN（canonical NaN）。

指定 `.spcompress` 限定符时，指令会在从张量内存加载数据的同时，执行内联稀疏压缩操作。压缩因子由 `.spfactor` 限定符指定。

`.spfactor` 唯一允许的值为 `.sp::2:4`，即对从张量内存加载的数据执行 2:4 压缩：

- 从张量内存读出的一半数据会保存到向量操作数 `cdata`；
- 描述所选元素索引的相应元数据，会保存到向量操作数 `mdata`。

每个数据元素的大小由 `.type` 指定，并且必须为 `.f32`。每个数据元素所对应的元数据索引大小由 `.idxsize` 指定，并且必须始终为 `.b2`。

`.rowop` 与可选的 `.abs` 限定符共同指定选择标准，用于从每四个元素组成的一组中选出两个元素。

当 `.red` 与 `.spcompress` 同时指定时，同一个 `.rowop` 和可选的 `.abs` 限定符也会指定归约运算符。

但需要注意：在这种情况下，如果指定 `.NaN` 限定符，它只适用于操作的归约部分，即 `.red` 部分，不适用于稀疏压缩部分。这是因为稀疏压缩操作始终会在输出中保留 NaN。

操作数 `mdata` 和 `cdata` 是用花括号包围的向量表达式，由一个或多个 `.b32` 寄存器组成。各操作数所需的向量长度可根据表 60 计算。

### 表 60：各操作数所需的向量长度

| 操作数 | 向量长度 |
|---|---|
| `mdata` | `ceil(num / 32)` |
| `cdata` | `num / 2` |

可选限定符 `.pack::16b` 可用于在加载过程中，将相邻列中的两个 16 位元素打包到一个 32 位元素中，具体见“打包与解包（Packing and Unpacking）”一节。

必需的 `.sync` 限定符表示：执行 `tcgen05.ld` 的线程必须等待 warp 中的所有线程都执行同一条 `tcgen05.ld` 指令，然后才能继续执行。

必需的 `.aligned` 限定符表示：warp 中的所有线程必须执行同一条 `tcgen05.ld` 指令。

在条件执行代码中，只有确定 warp 中的所有线程都会对条件得出相同判断结果时，才能使用 `tcgen05.ld` 指令，否则行为未定义。

如果出现以下任一情况，`tcgen05.ld` 的行为未定义：

- 并非所有线程都使用相同的 `taddr` 值；
- warp 中有任何线程已经退出。

`tcgen05.ld` 指令以异步方式执行，更多详细信息见“第五代 TensorCore 操作的内存一致性模型”一节。

## PTX ISA 说明

- 在 PTX ISA 8.6 版本中引入。
- `tcgen05.ld.red` 在 PTX ISA 8.8 版本中引入。
- `tcgen05.ld{.red}.spcompress` 在 PTX ISA 9.4 版本中引入。

## 目标 ISA 说明

支持以下架构：

- `sm_100a`；
- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_100f` 或更高架构；
- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_110f` 或更高架构。

`tcgen05.ld.red` 支持以下架构：

- `sm_101a`（从 PTX ISA 9.0 版本开始更名为 `sm_110a`）。

从 PTX ISA 8.8 版本开始，还支持以下特定架构家族：

- 同一家族中的 `sm_101f` 或更高架构（从 PTX ISA 9.0 版本开始更名为 `sm_110f`）；
- 同一家族中的 `sm_103f` 或更高架构；
- 同一家族中的 `sm_110f` 或更高架构。

`tcgen05.ld{.red}.spcompress` 支持以下架构：

- `sm_107a`。

## 示例

```ptx
tcgen05.ld.sync.aligned.32x32b.x2.b32
    {r0, r1}, [taddr1];

tcgen05.ld.sync.aligned.16x128b.x4.b32
    {r0, r1, r2, r3, r4, r5, r6, r7}, [taddr2];

tcgen05.ld.red.sync.aligned.16x32bx2.x8.u32.max
    {r0, r1, r2, r3, r4, r5, r6, r7},
    redVal, [taddr3], 16;

tcgen05.ld.red.spcompress.sync.aligned.32x32b.x32.max.sp::2:4.abs.f32.b2
    {mdata_0},
    {r0, r1, r2, r3, r4, r5, r6, r7,
     r8, r9, r10, r11, r12, r13, r14, r15},
    redval, [taddr];
```
