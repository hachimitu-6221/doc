```
mbarrier.init{.layout}{.shared{::cta}}.b64 [addr], count;
.layout = { .layout::v0, .layout::v1 }
```
**描述**
`mbarrier.init` 用无符号 32 位整数 `count` 初始化由地址操作数 `addr` 指定的位置处的 `mbarrier` 对象。`.layout` 限定符指定用于初始化该 `mbarrier` 对象的布局。如果未显式指定，则初始化一个 `.layout::v0` 的 `mbarrier`。更多细节参见“mbarrier 对象的布局”。

操作数 `count` 的合法取值范围取决于 `.layout`，如下所示：
- 对于使用 `.layout::v0` 的 `mbarrier`：`[1, …, 220 - 1]`
- 对于使用 `.layout::v1` 的 `mbarrier`：`[1, …, 29 - 1]`

`mbarrier` 对象的各组成部分按如下方式初始化：

- primary phase 和 conditional phase 初始化为零。
- expected arrival count 和 pending arrival count 初始化为 `count`。
- 初始 transaction count，即 `tx-count`，初始化为零。
- 对于使用 `.layout::v1` 的 `mbarrier` 对象，primary phase 对应的 payload report 初始化为零。

如果未指定状态空间，则使用 Generic Addressing。如果由 `addr` 指定的地址不落在 `.shared::cta` 状态空间的地址窗口内，则行为未定义。

操作数 `addr` 支持的寻址模式如“地址作为操作数”中所述。操作数 `addr` 的对齐要求如“mbarrier 对象的大小和对齐”中所述。

对包含有效 `mbarrier` 对象的内存位置执行 `mbarrier.init` 操作的行为未定义；在将该内存位置改作任何其他用途（包括另一个 `mbarrier` 对象）之前，必须先使用 `mbarrier.inval` 使该 `mbarrier` 对象失效。

**PTX ISA 说明**
在 PTX ISA 版本 7.0 中引入。
在 PTX ISA 版本 7.8 中引入对 `.shared` 上子限定符 `::cta` 的支持。
在 PTX ISA 版本 9.3 中引入对 `.layout` 限定符的支持。
**目标 ISA 说明**
需要 sm_80 或更高版本。
限定符 `.layout` 需要 sm_90 或更高版本。
**示例**
```ptx
.shared .b64 shMem, shMem2, shMem3;
.reg    .b64 addr;
.reg    .b32 %r1;

cvta.shared.u64          addr, shMem2;
mbarrier.init.b64        [addr],   %r1;
bar.cta.sync             0;
// ... 对 addr 的其他 mbarrier 操作

mbarrier.init.shared::cta.b64 [shMem], 12;
mbarrier.init.layout::v1.shared::cta.b64 [shMem3], 4;
bar.sync                 0;
// ... 对 shMem 的其他 mbarrier 操作
// ... 对 shMem3 的其他 mbarrier 操作
```
