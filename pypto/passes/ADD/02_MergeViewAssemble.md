### 1. RAWTENSOR 声明表“瘦身”（12 → 9）

最直观的变化是 Buffer 数量从 12 个减少到了 9 个。

- **删除了什么**：`@11"INCAST_LOCAL_BUF0"`、`@13"INCAST_LOCAL_BUF1"`、`@15"OUTCAST_LOCAL_BUF0"` 这三个大小为 3 的中间 Buffer 被移除了。
- **为什么删除**：在 `01_ExpandFunction` 中，编译器为了“切块”，先申请了 3 个和原张量一样大的“跳板 Buffer”，然后再从跳板里切小块。这显然是浪费的——既然最终只是要取 [0:2] 和 [2:3]，为什么不能直接从原张量里切？

### 2. 数据流“去中介化”

对比两段 IR 的 Op 执行链路，你会发现“中间商”被干掉了：

**在 `01_ExpandFunction` 中（有中间商）：**

1. 先从原输入 `%11@10` 取一个完整的 3 元素视图 `%12@11`（跳板 A）
2. 再从跳板 A 里切出 [0:2] 和 [2:3] 的小块
3. ADD 算完后，先写到一个完整的 3 元素输出跳板 `%18@15`
4. 最后再从跳板写回真正的输出 `%17@14`

**在 `02_MergeViewAssemble` 中（直达）：**

1. 直接从原输入 `%11@10` 切出 [0:2] 和 [2:3] 的小块（`TILE_VIEW` 的 `from offset` 变成了绝对偏移）
2. ADD 算完后，**直接写回**真正的输出 `%17@14` 的对应偏移位置

### 3. 具体 Op 行的变化细节

- **TILE_VIEW 的 `from offset` 变化**：
    - 以前：从跳板 `%15@13` 取 `offset:[2]`
    - 现在：直接从原输入 `%14@12` 取 `offset:[2]`
    - **意义**：偏移量从“相对跳板”变成了“相对原张量”，数学上等价，但少了一层间接引用。
- **TILE_ASSEMBLE 的目标变化**：
    - 以前：写到中间跳板 `%18@15`，然后再由另一个 `TILE_ASSEMBLE` 搬一次
    - 现在：一步到位，直接写到最终输出 `%17@14` 的 `offset:[0]` 或 `offset:[2]`
### 4. 这个 Pass 的意义
这一步是编译器在做 **“死代码/冗余搬运消除”**：
- **省内存**：白嫖了 3 个大小为 3 的 Buffer（虽然本例中是常量大小，但在大模型里这种优化能省下可观的 SRAM）。
- **省指令**：去掉了 2 个无意义的 `TILE_VIEW` 和 1 个无意义的 `TILE_ASSEMBLE`，后续 Pass 生成的汇编指令会更少。
- **为后续优化铺路**：数据流越简单（直接源→直接目的），后续的 `06_GenerateMoveOp` 在生成 DMA 搬运指令时就越不容易出错，也越容易做合并优化。
